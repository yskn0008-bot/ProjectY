# Clarity v4｜iPhone操作接続パイロット

## 現在の達成状況
- 実機検証済みのv3は変更しない。本v4は別名の隔離試作。
- 元のv3同様、原文は既存YOS Inboxへ保存・読戻し、その後のみ後続処理。
- 1回の入力を最大6件に分解し、既存Tasks/Shopping/Diary/Lifeへ安全な項目を登録。
- iPhone実行は明示的なタイマー（1〜60分）または画面明るさ（5〜100%）のどちらか1件のみ。全て原文との一致・範囲・実行前レシート保存で検査。
- 引用文中の操作らしい文字列は実行せず、独立した1行の明示操作だけを受理。同一受付IDでは一度目の操作完了後も2件目を実行しない。
- 同じ入力の24時間以内の重複操作禁止。操作命令を記録した後にショートカットアクションへ渡す。
- ショートカットのアクションから復帰したときだけ「アクション復帰」を記録（端末状態の実測ではない）。異常終了・通信結果不明は自動再試行しない。
- Siriの自由会話へ直接命令を送るのではなく、Siriでも利用されるiOSのショートカット操作を使う。

## 安全制約
- GitHub main、iPhoneの既存v2/v3、Notion DB名を変更しない。
- 支払い、送信、削除、外部公開、家電制御、アラーム、カレンダーは保留。
- ChatGPT出力から直接パラメータをiPhoneへ流さず、Scriptableで本人の原文を再照合し具体値を抽出する。
- 同じ原文を24h再送しても既存受付IDを使うので端末操作は再実行されない。新しい命令を操作したい場合は異なる原文にする必要がある（実験上の制限）。

## v3と試作v4の分離
- v4だけのローカル受領台帳 `YOS Clarity Device Pilot v4 Receipts.json` と受付ID `clarity:device4-…` を使う。v3の台帳や再送ルールを読み書きしない。
- Notion Inboxは共通の既存正本だが、v4専用IDが新規記録に付く。
- 1入力につき端末操作は最大1件。アラーム、カレンダー、外部送信、家電は今回の試作対象外。

## 2026-11-17 実機AI形式エラーへの対応
- 実機で「タイマー3分」を入力した際、既存YOS Inboxに原文は保存されたが、AI出力の形式が不正として端末操作は安全停止した。モデルの生出力は未取得で、文字列改変・返答形式のどちらが原因かは未確定。
- 単独で完全一致する明示的なタイマー（1〜60分）・画面明るさ（5〜100%）だけ、本人の保存済み原文を端末内で直接判定。AI形式が不正でも対象コマンドの意味を生成せず実行できる。その他や複合入力の形式不正は従来どおり安全停止。
- 「タイマー3分」のコロンなし入力にも対応。同一受付の24時間以内の再実行、操作結果不明時の再実行、2つめの端末操作は引き続き停止。
