# YOSナビ v106 ネットワークマーカー境界の安全記録

## 目的

YOSナビの承認済み実行資産に付与するネットワーク配信マーカーについて、現行世代の完全一致だけを強制ネットワーク取得に使い、不正形式、空値、旧世代、担当外通信へ処理範囲を広げない既存条件を回帰テストとして保存する。

## 固定する安全条件

- マーカーはYOSナビ専用query parameter `yos-nav-source`からだけ取得する。
- 現行マーカーは`network-${BUILD}`との完全一致の場合だけ強制ネットワーク取得に使う。
- 旧世代マーカーは強制ネットワーク判定より先に専用復旧処理へ渡す。
- 空値、不正形式、部分一致、未来の未承認形式を強制ネットワーク取得へ拡張しない。
- マーカー処理はYOSナビ範囲内かつ`STATIC`登録済みの承認済み資産に限定する。
- マーカー処理からCache Storage、IndexedDB、localStorage、担当外機能を変更しない。
- Taxi、Life、YOS、server、DB、乗車履歴、同期API、共通機能へ直接介入しない。

## 変更範囲

- `nav/tests/network-marker-boundary-safety.test.mjs`
- `nav/YOS_NAV_V106_NETWORK_MARKER_BOUNDARY_SAFETY.md`

YOSナビの実行時コード、画面、地図、現在地取得、期待値計算、営業判断、外部ナビ遷移は変更しない。

担当外のTaxi、Life、YOS、DB、乗車履歴、同期API、server、共通機能にも変更を加えない。

## 確認方法

GitHub Actions「YOSナビ Safety」で新規テストと既存の安全回帰テストを実行する。

## 未確認事項

- GitHub Actions「YOSナビ Safety」の最終結果。
- Codex governanceの最終結果。
- PRの競合と未解決レビュー。
- iPhone SE3 Safariで現行マーカー付き資産だけが同一画面のネットワーク配信へ固定されること。
- 不正形式や空のマーカー付き要求が通常の安全な配信選択へ戻ること。
- Vercel/CDN更新境界で部分一致マーカーが誤って強制ネットワーク扱いされないこと。
- 公開環境で担当外PWAの通信へ影響しないこと。
