# YOSナビ v106 画面単位配信先分離の安全記録

## 目的

YOSナビのService Workerが、キャッシュ配信またはネットワーク配信の選択を画面単位で保持し、一方のSafariタブやホーム画面PWAで発生した切替を別画面へ波及させない既存条件を回帰テストとして固定する。

## 変更範囲

- `nav/tests/client-serving-isolation-safety.test.mjs`
- 本記録ファイル

製品コード、Service Worker本体、画面、地図、現在地取得、期待値計算、営業判断、外部ナビ遷移は変更しない。

Taxi、Life、YOS、DB、乗車履歴、同期API、server、共通機能は変更しない。

## 固定する安全条件

1. 配信先は`CLIENT_SERVING_CACHES`で画面IDごとに保持する。
2. ナビゲーションでは`resultingClientId`を優先し、存在しない場合だけ`clientId`を使用する。
3. 承認済み実行資産は要求元の`clientId`だけを参照・更新する。
4. ネットワーク配信への固定は要求元画面だけに記録する。
5. 終了済み画面の記録だけを削除し、利用中画面の記録を一括削除しない。
6. 画面単位固定の処理からCache Storage本体、localStorage、IndexedDB、担当外機能、外部遷移を変更しない。

## 確認方法

GitHub Actions `YOSナビ Safety` と `Codex governance` で次を確認する。

- 新規回帰テストを含む全YOSナビ安全テストが成功すること
- 変更が`/nav/`内のテストと記録だけであること
- 未解決レビューと競合がないこと

## 未確認事項

- iPhone SE3 Safariで複数タブを開いた場合、一方のネットワーク固定が他方へ波及しないこと
- ホーム画面PWAとSafariタブを同時利用した場合、配信先固定が画面ごとに分離されること
- 画面終了後にService Workerの画面固定記録が適切に整理されること
- Vercel/CDN更新境界で画面ごとの世代整合性が維持されること
- 公開環境で担当外PWAへ影響しないこと
