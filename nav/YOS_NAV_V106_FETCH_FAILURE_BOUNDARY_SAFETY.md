# YOSナビ v106 fetch失敗境界 安全確認記録

## 目的

YOSナビのService Workerが通信失敗や不正な更新境界に遭遇した場合でも、未検証資産、旧キャッシュ、担当外機能へ処理を広げず、安全な応答だけを選ぶ既存条件を回帰テストとして固定する。

唯一の人格・司令塔の正式名称は「YOS」。明確な名称変更指示がない限り、チャット名、タスク名、画面名、役割名を含めて名称変更、言い換え、派生名への置換を行わない。

## 固定する安全条件

- GET以外の要求へService Workerが介入しない。
- YOSナビ画面の配信失敗時は、検証済みネットワーク応答を再取得し、それも失敗した場合は明示的なエラー応答にする。
- 現行ネットワークマーカー付き資産の取得失敗時は、旧キャッシュや別世代の資産へ戻さない。
- 旧世代マーカー付き資産は専用復旧応答で処理を終了し、通常資産配信へ流さない。
- 担当外要求は保存領域や画面単位の配信先固定を変更せず、通常fetchへ委譲する。
- Taxi、Life、YOS、server、DB、乗車履歴、同期API、共通機能へ介入しない。

## 変更範囲

- `nav/tests/fetch-failure-boundary-safety.test.mjs`
- `nav/YOS_NAV_V106_FETCH_FAILURE_BOUNDARY_SAFETY.md`

製品コード、画面、地図、現在地取得、期待値計算、営業判断、外部ナビ遷移、Service Worker本体は変更しない。

## 確認方法

GitHub Actionsの`YOSナビ Safety`と`Codex governance`を実行し、既存安全テストを含む全検査の成功を確認する。
