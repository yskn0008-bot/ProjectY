# YOSナビ v106 インストール失敗時ロールバック安全記録

## 目的

YOSナビのService Worker更新中に重要資産の取得・検証・保存が失敗した場合、不完全な現行キャッシュを残さず、既存の有効な退避キャッシュや担当外機能へ影響させない既存条件を回帰テストで固定する。

## 変更内容

- `nav/tests/install-rollback-safety.test.mjs`を追加
- 全重要資産の検証保存後にオフライン完成状態を再確認する条件を固定
- 完成確認後だけ`skipWaiting`へ進む実行順序を固定
- 取得・検証・保存・完成確認の失敗時に不完全な現行キャッシュだけを削除する条件を固定
- キャッシュ削除後もエラーを再送出し、失敗したService Workerを有効化しない条件を固定
- 既存の退避キャッシュ、画面別配信先固定、Taxi、Life、YOS、serverへ触れない条件を固定

## 変更範囲

- `/nav/`内のテストと記録のみ
- YOSナビの実行時コード、画面、地図、現在地取得、期待値計算、営業判断、外部ナビ遷移は変更しない
- Taxi、Life、YOS、DB、乗車履歴、同期API、server、共通機能は変更しない

## 確認方法

GitHub Actions「YOSナビ Safety」で以下を確認する。

- 新規テストのJavaScript構文
- 重要資産保存→オフライン完成検査→`skipWaiting`の順序
- 失敗時の現行キャッシュ限定削除
- 削除後のエラー再送出
- 退避キャッシュ・画面別配信先・担当外パスを変更しないこと
- 既存YOSナビ安全回帰テストとの同時成功

## 未確認事項

- GitHub Actions「YOSナビ Safety」の結果
- Codex governanceの結果
- PRの競合・レビュー状態
- iPhone SE3 Safariで更新中に一部資産取得を失敗させた場合の旧Service Worker継続
- Vercel/CDN障害時に不完全な現行キャッシュが残らないこと
- main反映後の再検査
