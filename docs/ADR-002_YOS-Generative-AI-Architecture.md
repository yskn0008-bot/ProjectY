# ADR-002：YOS専用生成AIを既存正本連携型で構築する

日付：2026-07-29  
状態：提案・YOS確認待ち  
対象Issue：#71

---

## 1. 背景

YOSの使命、判断順位、Google Drive正本、Project75、PWA、Mission Controlはすでに存在する。

一方、現在の `/yos/` は相談文をコピーして既存ChatGPTチャットを開く入口であり、Google Drive正本やProject75を自動参照する専用生成AIではない。

YOS専用生成AIには次が必要である。

- 正本の最新版を参照する
- 専門領域を自動選択する
- Project75を検索する
- 確定、仮説、未確認、矛盾を区別する
- 回答根拠を残す
- 新情報を保存候補として扱う
- APIキーと個人情報を安全に扱う
- 既存PWAと既存データを壊さない

---

## 2. 決定案

YOS専用生成AIを、次の構成で作る。

1. 既存の `/yos/` PWAを利用する
2. PWAとOpenAIの間に安全なバックエンドを置く
3. OpenAI Responses APIを使用する
4. 初期モデルは `gpt-5.6-terra` を第一候補とする
5. Google Driveの正本は、必要時にバックエンドが直接取得する
6. Project75はGoogle Sheets APIで必要範囲だけ検索する
7. 正本をOpenAIのVector Storeへ常時複製しない
8. 長期記憶は既存方針に従い、非公開Google Sheetsで管理する
9. AIは保存候補を作るだけとし、正本を無承認で変更しない
10. OpenAI Responses APIは `store: false` を基本とする
11. APIキー、Google秘密鍵、個人情報を公開GitHubやPWAへ保存しない
12. 本人認証はGoogleアカウント認証を第一候補とする

---

## 3. 理由

### 3.1 既存資産を維持できる

YOS PWA、Google Drive正本、Google Sheets、Mission Controlを作り直す必要がない。

### 3.2 正本の鮮度を保てる

Googleドキュメントを直接取得するため、検索用複製の更新漏れを減らせる。

### 3.3 個人情報の送信量を抑えられる

質問に必要な範囲だけをOpenAIへ送る。

日報原本画像、氏名、乗務員番号、秘密情報を毎回送らない。

### 3.4 根拠を追跡できる

取得した文書ID、更新日時、シート名、セル範囲を回答監査ログへ残せる。

### 3.5 無承認変更を防げる

読み取りと回答生成を先に実装し、書き込みは保存候補の承認後に限定する。

### 3.6 運用をシンプルにできる

初期段階では1つのモデル、1つのAPI、既存Google環境を使う。

---

## 4. 採用する構成

```text
YOS PWA
  ↓
YOS APIバックエンド
  ├─ Google本人認証
  ├─ Google Drive / Docs取得
  ├─ Google Sheets検索
  ├─ 情報分類・プライバシー処理
  ├─ OpenAI Responses API
  ├─ 根拠整形
  └─ 監査・保存候補
```

### バックエンド

- TypeScript
- Node.js互換
- 第一候補：Vercel Functions
- 中核処理はホスティング依存にしない

### AI

- API：OpenAI Responses API
- 初期モデル：`gpt-5.6-terra`
- 初期推論設定：`medium`
- 保存：`store: false`
- 出力：Structured Outputs

### データ

- 正本：Googleドキュメント
- 営業データ：Project75 Google Sheets
- 長期記憶：新規の非公開YOS Memory Google Sheet
- コード・設計・履歴：GitHub

---

## 5. 承認境界

### AIが自動で行ってよい

- 正本の読み取り
- Project75の読み取り
- 必要範囲の集計
- 確定、仮説、未確認、矛盾の分類
- 回答生成
- 保存候補の作成
- 個人情報を除いた技術監査ログ

### AIが承認なしで行ってはいけない

- Masterの変更
- Change Logの変更
- Project75の修正
- 長期記憶の確定保存
- 外部への送信
- 費用が大きく増える処理
- 新しい人格やLabの作成
- `/taxi/`、`/life/` の変更

---

## 6. 却下した案

### 6.1 独自基盤モデルを一から学習する

費用、データ量、運用負担が大きく、現在の課題解決に不要なため却下する。

### 6.2 ChatGPTの会話記憶だけに依存する

正本の更新、根拠追跡、確定・仮説分離、再発防止が保証できないため却下する。

### 6.3 OpenAI File Searchを最初から正本にする

Googleドキュメントとの二重管理になり、更新漏れと古い複製の問題が生じるため却下する。

File Searchは将来の検索用補助としてのみ再検討する。

### 6.4 APIキーをPWAへ保存する

公開、漏えい、不正利用の危険があるため却下する。

### 6.5 正本を毎回すべてモデルへ送る

費用、速度、個人情報、コンテキスト肥大化の問題があるため却下する。

### 6.6 AIによる自動書き込みを最初から許可する

誤分類、誤更新、正本破壊の危険があるため却下する。

### 6.7 新しい管理サービスを大量に追加する

操作場所と運用コストが増えるため却下する。

---

## 7. 良い影響

- YOSが毎回正本を参照できる
- 同じ引き継ぎを繰り返しにくくなる
- Project75を根拠に回答できる
- 未確認情報の断定を防げる
- 回答の根拠を確認できる
- 既存PWAを育てられる
- 将来のLife、Money連携へ拡張できる

---

## 8. 注意点

- バックエンドの新設が必要
- Google OAuthとサービスアカウントの設定が必要
- OpenAI APIはChatGPT Plus料金とは別料金
- 標準のAPI不正利用監視ログは最大30日保持される場合がある
- Vercel利用可否は未確認
- Google Sheetsは大規模な全文検索には限界がある
- 長期記憶の保存期間と削除ルールが必要
- 健康、位置、原本画像の送信基準が必要

---

## 9. 再検討条件

次のいずれかが発生した場合は、本ADRを再検討する。

- Google Drive直接検索では回答速度が不足する
- 資料数が増え、必要部分の取得精度が低下する
- API料金が承認予算を継続的に超える
- Google Sheetsでは長期記憶を安全に管理できない
- 日本リージョンまたはZero Data Retentionが必要になる
- Vercelが利用できない
- 評価で `gpt-5.6-terra` より適切なモデルが確認される

---

## 10. 実装前の承認事項

YOSは次を判断する。

1. 本構成を採用するか
2. Vercelを第一候補としてよいか
3. Google認証を採用してよいか
4. YOS Memory Google Sheetを新設してよいか
5. `gpt-5.6-terra` を初期モデルとしてよいか
6. `store: false` を標準としてよいか
7. 月額予算をいくらにするか
