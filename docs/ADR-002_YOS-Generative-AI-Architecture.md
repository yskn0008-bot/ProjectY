# ADR-002：YOS専用生成AIを既存正本連携型で構築する

日付：2026-07-29  
状態：提案・YOS確認待ち  
対象Issue：#71

---

## 1. 背景

YOSの使命、判断順位、Google Drive正本、Project75、PWA、Mission Controlはすでに存在する。

一方、現在の `/yos/` は相談文をコピーして既存ChatGPTチャットを開く入口であり、Google Drive正本やProject75を自動参照する専用生成AIではない。

必要な機能：

- 正本の最新版を参照する
- 専門領域を自動選択する
- Project75を検索する
- 確定・仮説・未確認・矛盾を区別する
- 回答根拠を残す
- 新情報を保存候補として扱う
- APIキーと個人情報を安全に扱う
- 既存PWAと既存データを壊さない

---

## 2. 決定案

1. 既存の `/yos/` PWAを利用する
2. PWAとOpenAIの間に安全なバックエンドを置く
3. OpenAI Responses APIを使用する
4. 初期モデル候補は `gpt-5.6-terra` とする
5. Google Drive正本は必要時にバックエンドが取得する
6. Project75はGoogle Sheets APIで必要範囲だけ検索する
7. 正本をOpenAI Vector Storeへ常時複製しない
8. 長期記憶は非公開Google Sheetsを第一候補とする
9. AIは保存候補を作るだけとし、正本を無承認で変更しない
10. Responses APIは `store: false` を基本とする
11. APIキー、秘密鍵、本人情報、非公開IDを公開GitHubやPWAへ保存しない
12. 本人認証はGoogleアカウント認証を第一候補とする

---

## 3. 理由

### 既存資産を維持できる

YOS PWA、Google Drive正本、Google Sheets、Mission Controlを作り直す必要がない。

### 正本の鮮度を保てる

Googleドキュメントを直接取得するため、検索用複製の更新漏れを減らせる。

### 個人情報を最小化できる

質問に必要な範囲だけをOpenAIへ送る。日報原本画像、氏名、乗務員番号、秘密情報を毎回送らない。

### 根拠を追跡できる

文書の内部識別子、更新日時、シート名、セル範囲を非公開の監査ログへ残せる。

### 無承認変更を防げる

読み取りと回答生成を先に実装し、書き込みは保存候補の承認後に限定する。

### シンプルに始められる

初期段階では1つのモデル、1つのAPI、既存Google環境を使う。

---

## 4. 構成

```text
YOS PWA
  ↓
YOS APIバックエンド
  ├─ Google本人認証
  ├─ Google Drive / Docs取得
  ├─ Google Sheets検索
  ├─ 情報分類・プライバシー処理
  ├─ OpenAI Responses API
  ├─ 根拠整形
  └─ 監査・保存候補
```

バックエンド候補：TypeScript、Node.js互換、Vercel Functions第一候補。

データの役割：

- 正本：Googleドキュメント
- 営業データ：Project75 Google Sheets
- 長期記憶：非公開YOS Memory Google Sheet
- コード・設計・変更履歴：GitHub

---

## 5. 承認境界

AIが自動で行ってよい：

- 正本とProject75の読み取り
- 必要範囲の集計
- 確定・仮説・未確認・矛盾の分類
- 回答生成
- 保存候補の作成
- 個人情報を除いた技術監査ログ

承認なしで行ってはいけない：

- Master、Change Log、Project75の変更
- 長期記憶の確定保存
- 不要な外部送信
- 費用が大きく増える処理
- 新しい人格やLabの作成
- `/taxi/`、`/life/` の変更

---

## 6. 却下した案

### 独自基盤モデルを一から学習する

費用、データ量、運用負担が大きく、現段階では不要。

### ChatGPTの会話記憶だけに依存する

正本更新、根拠追跡、確定・仮説分離、再発防止を保証できない。

### OpenAI File Searchを最初から正本にする

Googleドキュメントとの二重管理になり、更新漏れと古い複製の問題が生じる。

### APIキーをPWAへ保存する

漏えい・不正利用の危険がある。

### 正本を毎回すべてモデルへ送る

費用、速度、個人情報、コンテキスト肥大化の問題がある。

### AIの自動書き込みを最初から許可する

誤分類、誤更新、正本破壊の危険がある。

---

## 7. 注意点

- バックエンドの新設が必要
- Google OAuthとサービスアカウントの設定が必要
- OpenAI APIはChatGPT契約とは別料金
- 標準のAPI監視ログ保持条件を確認する必要がある
- Vercel利用可否は未確認
- 長期記憶の保存期間と削除ルールが必要
- 健康、位置、原本画像の送信基準が必要
- 公開GitHubへ本人情報や非公開資源IDを置かない

---

## 8. 再検討条件

- Google Drive直接取得では速度が不足する
- 資料数増加で必要部分の取得精度が低下する
- API料金が承認予算を継続的に超える
- Google Sheetsでは長期記憶を安全に管理できない
- Zero Data Retention等が必要になる
- Vercelが利用できない
- 評価で別モデルの方が適切と確認される

---

## 9. 実装前の判断事項

1. 本構成を採用するか
2. Vercelを第一候補としてよいか
3. Google認証を採用してよいか
4. 非公開YOS Memory Google Sheetを新設してよいか
5. `gpt-5.6-terra` を初期候補としてよいか
6. `store: false` を標準としてよいか
7. 月額予算とログ保存期間
